# The documentation is read out of the code

One sentence, taken from `amy`, where it is already load-bearing:

> Anything a machine can read out of the code is never written by hand.

## Where this repository stands

Three documents. [`docs/method.md`](../docs/method.md) is written by hand.
[`docs/rules.md`](../docs/rules.md) is written by hand above its first `## L`
heading and generated below it, by `sf docs`, out of the catalog.
[`README.md`](../README.md) is 924 lines, all of them by hand.

One guard covers all of that: `L2.DERIVED_ARTIFACTS_MATCH_THEIR_SOURCE` runs
`sf docs` and then diffs `docs/rules.md`, so that one page cannot drift. The
generated half of the documentation is one page, at file granularity, from one
source.

## What that costs, measured this morning

The README carried four claims a machine could have read: "34 rules" in the
opening paragraph, "34 rules, plus 4 templates" in the layer section, "30 rules
enabled, 30 proven to fire", and "Four of the 34 are switched off here and one
is frozen". The catalog holds 38 rules, 34 are enabled in this repository, all
34 are proven to fire, four are switched off and three violations are frozen.
Every one of those numbers was wrong, in the front door of the repository whose
argument is that documentation drift is a thing you can check. They were
corrected by hand, which is the move this plan exists to stop needing.

## What to copy, and what changes on the way

`amy` generates with `npm run docs:generate`, guards with `npm run docs:check`
inside `npm run gate`, and writes the convention down in
`docs/development/documentation.md`. Four parts of it are worth taking.

**Marker blocks, instead of file granularity.** A generated table sits between
`<!-- sf:generated <block> -->` and `<!-- sf:end <block> -->` on a page that is
otherwise somebody's writing. Everything outside the markers is never touched;
everything inside is replaced. That is what lets an argued page carry a
generated count without becoming a generated page. Two cases are errors rather
than warnings: a page naming a block nothing produces, and a block nothing
places. A reference section that quietly renders nothing is worse than a build
that fails, and a fact the documentation holds and never shows is the same
failure as one that is out of date.

**A check that writes nothing.** `sf docs --check` writes nothing, exits
nonzero, lists the pages that would change and names the command that fixes
them. This repository needs that more than `amy` does: the rule guarding
`docs/rules.md` today runs `sf docs` and diffs the result, so a check rewrites
the file it is checking, in the middle of a run that is supposed to be
read-only. The policy already makes this argument for the release instance of
the same rule, whose first draft ran `sf lock` mid-check and erased the
evidence the lock rules exist to read. The docs instance is the same bug,
unfixed.

**No timestamps, anywhere.** A generated file that changes every time it is
generated cannot be checked for drift. So nothing generated carries a clock, a
duration, a run count or a digest of something outside the repository.

**Navigation that comes from the file system.** `docs/nav.yaml` says which
groups exist and in what order, because nothing in a directory listing says
that "Start here" comes before "Reference". Which pages exist, and their order
inside a group, comes from the directory and each page's front matter, so
adding a page needs no second list. With two pages that machinery costs more
than it returns, so it waits for the page count to justify it, and the manifest
that a website reads waits for a website.

## What is derived here, and from where

| Fact | Read from | How |
| :-- | :-- | :-- |
| A rule's layer, title, statement, why, fix and defaults | `catalog/` | Already generated by `sf docs` |
| How many rules ship, are enabled, are off, are proven, are frozen | The catalog, the policy, the ratchet | Counted, never typed |
| Why a rule is switched off | The YAML comments in `.software-factory/policy.yaml` | The comments are where the reasons already live |
| Subcommands, long flags and defaults | The clap definition in [`src/main.rs`](../src/main.rs) | `accepted_commands()` already reads it for `L4.RULE_PROSE_NAMES_A_REAL_COMMAND` |
| The templates the interview fills in | `templates/` | Counted and listed with the rule each produces |
| The interview's decision tree | `interview/decisions.yaml` | Already exposed by `sf interview --json` |
| Which languages a rule has a query for | The catalog's per-language queries | The table nobody can keep by hand |
| The skills, and what each is for | `skills/*/SKILL.md`, registered in [`src/skills.rs`](../src/skills.rs) | Front matter, read from the same constant `sf skills` writes from |

The per-language row is the one worth pausing on. "Which rules actually apply
to Ruby" is the first question an adopter asks, this repository answers it
today by reading YAML by hand, and the answer moves every time a language
adapter grows a query.

## The word "gate", used precisely

Documentation freshness is L2, not L3. It is decidable by reading files, needs
no evidence manifest and no run of the product, so it belongs with the derived
artifacts and not with the gates. Calling it a gate would be the first step
towards sealing evidence about something a diff already proves.

Concretely: no new catalog rule ships.
`L2.DERIVED_ARTIFACTS_MATCH_THEIR_SOURCE` keeps the job and its `run` becomes
`sf docs --check`. The unplaced-block and unknown-block cases are the
generator's own errors, because they are about the generator's inputs rather
than about the repository. An adopting project wraps its own generator in the
same rule, which is the extension point that already exists.

## Non-goals

The drafting half. `amy` has `npm run docs:draft`, which asks an agent for
prose about a surface nobody has documented, never runs in the gate and is
never trusted without review. Here the undocumented surface is small, and
`L4.EVERY_RULE_HAS_A_WHY` plus the rules document already force prose for every
rule, so a drafter would be a tool looking for work.

Generating the README. It is the front door, it is argued rather than listed,
and generating it would cost the one piece of writing that makes anybody try
this at all. It carries blocks. It is not one.

## Acceptance criteria

- [ ] `sf docs --check` writes nothing, exits nonzero, names every page that
      would change and the command that fixes them
      (proof: test:src/docs.rs)
- [ ] `sf check` no longer rewrites `docs/rules.md` while checking it, so a
      read-only run stays read-only
      (proof: test:src/docs.rs)
- [ ] A generated block replaces only what sits between its markers, on a page
      whose other content is left byte-identical
      (proof: test:src/docs.rs)
- [ ] A page naming a block nothing produces fails, and a block nothing places
      fails
      (proof: test:src/docs.rs)
- [ ] Every count in `README.md` and `docs/` comes from a block: rules
      shipped, enabled, switched off, proven, and violations frozen with their
      review date
      (proof: test:src/docs.rs)
- [ ] The documented command surface is read out of the clap definition,
      through the same `accepted_commands()` that
      `L4.RULE_PROSE_NAMES_A_REAL_COMMAND` reads
      (proof: test:src/main.rs)
- [ ] Which rules carry a query for which language is a generated table, and it
      changes when a language adapter gains a query
      (proof: test:src/docs.rs)
- [ ] Nothing generated carries a value that differs between two runs on the
      same commit
      (proof: test:src/docs.rs)
- [ ] The convention itself is written down in `docs/`, next to the rules it
      is enforced by, rather than living in this plan
      (proof: test:src/checks/cadence.rs)
- [ ] Whether this repository grows `docs/nav.yaml` and a manifest a site
      reads is decided by the page count, not by this plan
      (proof: unspecified:a manifest is worth generating only once something
      consumes it, and no check can tell whether anything does)
- [ ] What an adopting repository gets from the tool, against what stays
      specific to this one, is settled before the extractors ship
      (proof: deferred:the extractor set for sf's own surface is not designed
      yet)

**Exit condition:** `sf docs --check` runs in this repository's gate, writes
nothing, and goes red when the code moves and a page does not; every number and
every table in `README.md` and `docs/` that a machine can read comes from a
marker block whose source is named in `docs/`; and adding a page or a generated
block requires no second list to be updated by hand.
